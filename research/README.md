# Исследовательские данные

`generate_demo.py` создаёт небольшой учебный граф переводов и сохраняет CSV в `demo_data`. Обычные и искусственно созданные схемы имеют явные метки сценария. Модель не должна видеть эти метки как входной признак. Набор создан для наглядной демонстрации, а не для оценки качества на реальных людях.

Временные признаки считайте только по переводам до момента заявки. Не используйте данные будущего. Чтобы исследовать обобщение, разделите данные по времени и по отдельным сценариям; не считайте, что 100% на собственном генераторе подтверждает работоспособность на реальных случаях.

На другом компьютере: `python research/generate_demo.py`, затем `python research/train_models.py --input research/demo_data/transactions.csv --output research/results`. Скрипт сравнивает логистическую регрессию, случайный лес и простой GraphSAGE на дневных срезах: вход графа содержит только предшествующую историю, а цель — метка получателя на следующий день. Это не проверка одной транзакции до её исполнения. Предусмотрено разделение по времени и получателям: метки целевых получателей не пересекаются, но их узлы могут присутствовать в ранних графах как соседи, а связанные кампании не выделены отдельно. Калибровка по validation пока отсутствует; учтите это в оценке.

Дополнительно включён небольшой независимый синтетический [набор Misata AML](https://www.misata.studio/datasets/aml-transactions-ground-truth) под CC0. Команды: `python research/unpack_misata.py`, `python research/adapt_misata.py --input research/data/misata/transactions.csv --output research/data/misata/adapted.csv`, `python research/train_models.py --input research/data/misata/adapted.csv --output research/aml-results`. Эксперимент также доступен кнопкой лаборатории. Метки показывают синтетические подозрительные AML-сценарии, а не факт мошеннической покупки; построенный граф разделяет счета и контрагентов на разные множества. Операции без контрагента исключаются. Доступность классов на временных отрезках и пригодность эксперимента пока не проверены.

После обучения лаборатория может показать отдельную графовую гипотезу для небольшой вручную заданной истории (до 500 учебных переводов). Это исследовательское соединение использует только переводы, предшествующие указанному времени; выход модели не откалиброван и не управляет реальным переводом. Распределение ручных примеров может отличаться от обучающих данных.

Текстовые примеры для учебного запуска создаёт `python research/generate_text_demo.py`; затем `python research/text_classifier.py --train research/text_demo/train.csv --test research/text_demo/test.csv`. Они состоят из искусственных шаблонов: результат не является оценкой на настоящих мошеннических страницах. Для исследования необходим независимый размеченный набор с источниками и группировкой по кампаниям. Локальный языковой прототип `local_context.py` принимает модель GGUF, не имеет полномочий на действия и выводит только гипотезы; не передавайте ему секреты. Для кнопки лаборатории необходимо самостоятельно установить `llama-cpp-python` и разместить совместимый локальный файл как `research/models/context.gguf`. Он не подключён к расширению; модель и результаты работы не поставляются.

Для сравнения извлечения сущностей предусмотрены `train_ner.py` (CRF) и `train_transformer_ner.py` (локальный трансформер). Оба требуют отдельных размеченных JSON: список объектов с `tokens` и BIO-метками `tags`; реальные секреты включать нельзя. Трансформер требует локально установленный checkpoint и зависимости `requirements-transformer.txt`. Встроена только макрооценка по токенам, а не полноценная оценка совпадения границ сущностей. Корпус и веса не включены, команды не запускались, сравнение на реальных страницах не выполнено.

Можно создать небольшой учебный корпус `python research/generate_ner_demo.py` и затем запустить `python research/train_ner.py --train research/ner_demo/train.json --test research/ner_demo/test.json --out research/ner-crf`. Он состоит из искусственных шаблонов и не заменяет проверку на независимых реальных страницах. Для трансформера используйте те же файлы и явно укажите путь к локальному checkpoint через `--model`.

SynSEPA отдельно проанализирован в `synsepa-audit.md`. Для графовых экспериментов открыт генератор [SantanderAI/gen-fraud-graph](https://github.com/SantanderAI/gen-fraud-graph) (Apache-2.0), но его типовые размеченные циклы описывают схемы отмывания денег. Применимость к платежам жертв мошеннических магазинов не доказана.

Для первичного анализа небольшого ранее рассмотренного веб-корпуса можно запустить `node research/evaluate_reviewed.cjs ../datasets/web_pages/reviewed_samples.json`. Скрипт читает только текстовые выдержки и количество полей, не открывает и не выполняет исходный HTML. Метки позаимствованы у источников, выборка очень мала; автоматический отчёт не является полноценной валидацией или оценкой качества на российских страницах. Данные корпуса в Git не включаются автоматически.
